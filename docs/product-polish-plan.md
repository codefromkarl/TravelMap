# 🎯 TravelMap 产品与展示优化方案（面试门面版）

> 目标：让这个项目在简历、GitHub、面试三关都「立得住」——
> **3 秒看懂（README/截图）· 30 秒动心（演示视频/首屏）· 3 分钟信服（现场 demo）**
>
> 基于 2025-08 现状诊断：功能已相当完整（多模型 Agent、地图路线、天气、分享、PWA、i18n、评测体系），
> 缺的是**「包装层」**：视觉记忆点、演示叙事、可量化的对外证据。

---

## 一、现状诊断（先认清优势与短板）

### ✅ 已经很强（面试可讲的硬货）
| 资产 | 说明 |
|------|------|
| 多模型 Agent 编排 | OpenAI/Anthropic/Google/DeepSeek/OpenRouter + 本地免费模型，带故障转移 |
| 工具调用体系 | 景点/天气/地理编码/预算/小红书数据源（4 路路由 + 自建 crawler） |
| 地图可视化 | Leaflet 自托管、图层切换、分日路线、风险热区、补给点 |
| 分享引擎 | 零依赖 Canvas 卡片 / LZ-String 短链 / 内联二维码 / Web Share API |
| 工程化 | 评测循环（eval loop + 归因分析 + A/B）、trace 瀑布、内容哈希缓存、CI 门禁 |
| 性能 | bundle 10.4MB→5.1MB、app 260KB、线上首屏 ~0.9s |
| 线上可用 | travel.codefromkarl.xyz 已部署，HTTP 200，1s 内返回 |

### ❌ 门面短板（本次要补的）
1. **README 零截图**——只有文字和 badge，面试官 3 秒内无法形成画面感（最致命）
2. **首页即应用**——没有落地页/hero，第一次点进来的人不知道「这是什么、能给我什么」
3. **「AI 感」不突出**——Agent 在后台干活，用户看不到「思考过程」，酷炫感打 5 折
4. **地图是静态的**——路线一次性画完，没有动画叙事，缺「哇」的一刻
5. **分享卡片偏朴素**——纯色渐变 + 白底文字，和「精美」有距离
6. **无演示视频**——面试官没空自己点，一个 60 秒视频能替你说话
7. **没有公开的量化报告**——评测体系是内部资产，面试时拿不出证据

## 二、核心策略：三个「门面」层级


## 四、P1 · 交互门面（1 周，酷炫感的核心）

### 4.1 首屏体验升级
- **欢迎层加「三选一」**：① 一键体验示例（已有）② 智能推荐目的地（已有 discover）③ 直接输入需求——把三件事做成三个大卡片，降低空想成本
- 首次加载给 hero 氛围：大标题 + 副标题 + 背景用极简世界地图轮廓（SVG 即可，零成本）
- 游客示例加载后加**轻引导浮层**（3 步：看地图 → 点标记 → 试分享），取代裸奔状态

### 4.2 地图「电影感」动画（最高性价比酷炫点）
现有 web/modules/ui/map.js 的 polyline 是一次性绘制，改成：
1. **路线渐进绘制**：每天的路线按景点顺序分段用 requestAnimationFrame 画出（dash 动画 + 端点圆点跟随）
2. **视口巡游**：动画开始时地图沿路线自动平移缩放（flyTo 链），像「上帝视角巡游」
3. **标记弹入**：景点 marker 按序缩放弹入（CSS transform，Leaflet divIcon 支持）
4. 动画可跳过（首次 1 次后默认关闭，设置里可开）
> 效果：生成行程 → 地图「自己讲了一遍故事」，用户不用看任何说明就懂了

### 4.3 Agent 工作台可视化（面试杀手锏）
把现有 waterfall.js（开发者 trace）升级出**面向用户的「AI 工作台」**：
- 生成行程时，聊天区上方出现横条流：🔍 搜索杭州攻略 → 🌤️ 查询 3 日天气 → 📍 解析景点坐标 → 🧮 计算预算 → ✏️ 生成行程
- 每一步带状态（进行中/完成/耗时）和图标，完成时打勾
- 让用户**看见 Agent 在思考**——这是「AI 产品」区别于「调用 API 的网页」的关键感知，面试时直接指着它讲工具调用编排
- 成本：把已有 span/trace 数据映射成用户态文案，约 1 天

### 4.4 行程数据卡片（专业性感知）
行程头部加一排统计徽章：
`🗓 3 天 · 📍 9 个景点 · 🚶 每日 8.2km · 💰 人均 ¥1,200 · 🌤 晴 25°C`
（数据后端已生成，前端拼装即可，半天）
> 让「AI 生成的行程」看起来像「专业旅行社的产物」

## 五、P2 · 产品方向（1-2 周，差异化叙事）

### 5.1 行程对比模式（推荐第一个做）
- 同需求一次生成 2 份方案：**舒适型 vs 紧凑型**（或 美食型 vs 文化型）
- 前端左右分栏对比：每日行程、总预算、景点数、体力指数
- 技术叙事：「引入 critic 自评环节，同一需求产出多方案并量化打分」——把评测体系复用起来
- 这是**产品差异化 + 技术深度的双重亮点**

### 5.2 公开评测报告页（把内部资产变成证据）
- 现有 eval loop 已产出结果（eval-results/），做一个 /eval.html 展示页：
  - 评测维度（信息完整性/路线合理性/预算准确性/安全评估…）+ 历史得分趋势图
  - 「第 N 轮迭代得分从 X → Y」的曲线——**面试最硬核的量化证据**
- 数据用静态 JSON 生成（构建时产出），无运行时成本

### 5.3 出行中模式（产品想象力）
- 一键切换「旅行中」：地图跟随定位、下一站 500m 提醒、天气突变预警（已有天气能力）
- 工作量中等，作为 P2 备选；时间紧可只做「行程倒计时 + 明日天气」卡片

### 5.4 短链生态闭环
- 分享短链已存在 → 加「**导入行程**」：粘贴他人短链 → 解析 → 变成自己的行程继续编辑
- 让分享从「展示」变成「协作」，闭环叙事完整，工作量半天

## 七、简历与面试叙事（怎么写、怎么讲）

### 7.1 简历项目段（模板）
> **旅图 TravelMap — 多智能体 AI 旅行规划系统**（个人项目，独立开发，线上可用）
> - 设计基于 pi 框架的 **Agent 编排架构**：规划/工具/后处理分层，串联景点搜索、天气、地理编码、预算 6+ 工具，支持 5 家 LLM 服务商动态路由与故障转移
> - 构建 **评估驱动开发闭环**：多维度行程质量评测 + 归因分析 + A/B，迭代优化 Prompt 与工具行为
> - 前端实现 **行程-地图联动可视化**：分日路线、风险热区、补给点；零依赖 Canvas 分享引擎（图片/短链/二维码）
> - 工程化：Vitest + Playwright（含自动录制演示视频）、CI 体积门禁、内容哈希缓存，**bundle 10.4MB→5.1MB，首屏 ~1s**；PWA + 三语言 i18n

### 7.2 面试 demo 脚本（3 分钟版）
1. **0:00 打开链接**：游客模式直接点「一键体验示例」（无需登录，无环境风险）
2. **0:30 地图动画**：路线绘制动画，讲「行程生成后地图自动巡游，前后端数据结构打通」
3. **1:00 点一个标记**：弹窗讲「坐标由地理编码工具解析，多数据源兜底」
4. **1:30 生成新行程**（环境允许时）：切到免费模型，看 Agent 工作台逐工具执行
5. **2:30 分享卡片**：生成海报 → 提「零依赖 canvas 引擎 + LZ-String 压缩短链」
6. **收尾**：「评测循环保证每次 Prompt 修改不回归，报告见 /eval.html」
> 关键：**每个演示点都对应一个可讲的工程决策**，不要只演示「能用」

### 7.3 常见追问预备
- 「为什么用 Leaflet 不用 Mapbox？」→ 自托管零成本、国内访问稳定、离线可用；商业化场景会考虑 Mapbox GL
- 「多模型路由怎么做的？」→ 服务商抽象层 + 健康检查 + 故障转移 + 成本优先级（XHS 数据源已用 priority/cost/all 策略，同一个模式）
- 「评测怎么量化？」→ 多维度打分 + 归因分析定位是哪一步（Prompt/工具/数据）导致的得分变化
- 「分享链接压缩原理？」→ LZ-String + 压缩编码，行程数据压到 URL 可容纳长度
